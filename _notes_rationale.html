DESIGN NOTE

왜 이렇게 했는가 — 화면별 설계 근거

아래 노트는 위쪽 4개 화면(왼→오른 순서)과 1:1 대응합니다 · IMP 번호 = 개선계획서 v1.0 항목

1키워드 사전 관리IMP-01 · IMP-06

왜 이렇게 했는가

  • C-01 오매칭의 근본 원인은 "정규식 부분문자열 매칭" — 코드를 고쳐도 표기 변형(React.js·ReactJS·리액트)은 못 잡으므로 사전 자체를 데이터로 분리
  • 표준 스킬(canonical)+별칭(alias) 2단 구조 → 분류·매칭·히트맵이 같은 사전을 공유해 결과가 어긋나지 않음
  • 매칭 테스트 패널: 사전 편집이 실제 매칭에 미치는 영향을 즉시 검증 — 편집→결과 확인 루프가 한 화면 안에 있어 블랙박스가 아님
  • 학과(테넌트) 칩: 사전은 학과 단위 리소스 → 전자과·디자인과는 사전만 교체, "학과별 채용관" 확장 구조를 UI에 명시

근거: cv-gap-analyser — 큐레이션 키워드 리스트가 spaCy NER보다 정확하다는 실증 · ESCO식 스킬 표준화 · 점핏 스킬 태그 분류 참고

2지원 현황 — 스킬 갭 액션IMP-03

왜 이렇게 했는가

  • "매칭 78"이란 숫자만으론 다음 행동으로 안 이어짐 → 부족 스킬을 카드 안에 노출하고 보완 액션을 체크리스트로 전환
  • 필수(critical)/우대(important) 색상 구분 — 어떤 갭이 서류 탈락에 치명적인지 즉시 구분, ResuMatch의 우선순위 패턴 차용
  • 진행률 1/3 누적 표시: 보완이 게이미피케이션처럼 보여 재방문·이어쓰기 유도 (리텐션 장치)
  • 학습 리소스는 사전 등록된 외부 링크 — AI 추천이 아니므로 "왜 이 리소스인가" 설명 가능, 투명성 철학 유지

근거: ResuMatch — 누락 스킬을 critical/important로 정렬 + 스킬별 학습 링크 제공 패턴

3키워드 히트맵 v2IMP-04

왜 이렇게 했는가

  • "의미상 커버"와 "단어 그대로 커버"는 다르다 — 78% vs 62%의 16%p 갭이 곧 ATS 검색 탈락 리스크
  • 2단 범례(정확 일치=실선 채움 / 별칭 일치=점선) — 기존 I-03 범례 불일치(색상과 수치 기준 불일치)를 구조로 해결
  • ATS 관점 리딩 패널: "k8s로 쓰면 Ctrl+F에 안 잡힌다"처럼 행동 지침까지 제시 — 점수가 아니라 코칭
  • 의미 유사도(임베딩) 축은 AI 보류로 제외 — 대신 exact/alias라는 결정론적 2축으로 분해해 같은 인사이트 확보

근거: cv-gap-analyser — 의미 유사도 vs 키워드 오버랩(ROUGE)을 2축으로 분리 표시하는 방식 · 사람인 ATS 채용 흐름 참고

4학과 취업 통계IMP-05

왜 이렇게 했는가

  • F-14의 StatusHistory는 이미 기록 중 — 새 수집 없이 집계만 하면 학과 취업지원실용 가치가 즉시 생김
  • 지원→서류→면접→최종 퍼널은 학과의 핵심 KPI — "우리 학과는 어디서 떨어지는가"를 한눈에
  • n<5 자동 마스킹: 소수 집단(2학년 인턴 등)은 재식별 가능 — 프라이버시를 설계로 해결하고 UI에 명시
  • 학과 이메일·학번으로 집계하므로 HireLink(탑다운 큐레이션)와 다른 moat — 학교 도입 이유(B2B2C)를 화면에 직접 표현

근거: HireLink 비교 — 매칭점수·코칭·학과 체인 부재 확인 · 점핏 부트캠프 채용관(코호트 단위 검증됨)

공통 원칙 — AI/임베딩 항목은 이번 범위에서 전면 보류: 의미 유사도 축·AI 추천·AI 생성 UI는 전부 없습니다. 모든 매칭·분류·코칭은 결정론적 규칙 + 큐레이션된 사전 데이터로 동작하며, 각 수치 옆에는 "왜 이 수치인가"를 설명하는 근거 UI를 배치했습니다 — 투명한 코칭이 HireLink·사람인과의 차별점입니다.
